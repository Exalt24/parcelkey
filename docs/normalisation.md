# Normalisation rules

`parcelkey/normalise.py`. Every function is pure. Each returns what it found and the ids of the rules that fired, and the ids are stored on the record (`source_record.norm_rules`, `contact_rules`) so a surprising result can be explained from one row. `python -m parcelkey explain --agency A crm:C00042` prints them.

The address parts are: unit, level, building, lot, street number (first and last), street name, street type (and suffix), locality, state, postcode. The type, flat type, level type and suffix lists are in `parcelkey/gnaf_codes.py`, copied from Geoscape's Appendix C (see [data-sources.md](data-sources.md)). Street types are written the G-NAF way, as the full word (`STREET`, not `ST`), with a street suffix after it when there is one (`STREET NORTH`). The same functions read G-NAF rows and messy text, so both sides of a match use one vocabulary.

## Address rules

| Rule id | What it does | Example |
|---|---|---|
| CASE_FOLDED | Upper case. Fires only when something was not upper case already. | `12 smith st` |
| PUNCT_STRIPPED | Characters other than letters, digits, `/`, `,`, `-`, `#` and space become spaces. Apostrophes are dropped. | `U5/12 Smith St.` |
| WHITESPACE_COLLAPSED | Runs of spaces are one space. | `12   Smith St` |
| UNIT_MARKER_WORD | `Unit`, `U`, `Apt`, `Apartment`, `Flat`, `Suite`, `Ste`, `Shop`, `Villa`, `Office`, `Townhouse`, `Room` or `#` followed by an id. An id is digits with an optional letter before (`G1`, FLAT_NUMBER_PREFIX) and after (`5A`), or one letter on its own (`Unit B`, `Flat A`, `Shop A`), also before a slash (`B/12 Smith St`). G-NAF keeps a flat letter in FLAT_NUMBER_PREFIX or FLAT_NUMBER_SUFFIX with no flat number, so `B` is a flat and the key `B` is the same on both sides. A lone letter counts only when a number stands somewhere behind it (`Unit B 12 Smith St`), because with none it could start the street (`Unit A Smith St` is left as it was). `Building`, `Bldg`, `Tower`, `Twr`, `Block`, `Blck`, `Penthouse`, `Duplex`, `Maisonette`, `Cottage`, `Studio`, `Loft`, `Bungalow` and `Tenancy` are G-NAF flat types too and read the same way, but only with a number or letter after them and only when another number follows (`Tower 3, 100 Pacific Hwy` is unit 3 of number 100; `Skyline Tower 12 Smith St` is a building named Skyline Tower at number 12, as before); they are not in the marker list that keeps a suburb from starting with one (Tower Hill, Cottage Point). When a unit is written as well, the tower is the building (`Tower 3, Unit 5, 12 Smith St`). | `Unit 5, 12 Smith St`, `Shop G12, 40 Smith St`, `Unit B, 12 Smith St`, `Building 2, 100 Pacific Hwy` |
| UNIT_NO_WORD_DROPPED | `No`, `No.`, `Number`, `Num` or `Nr` between a unit word and its id is a label and is dropped. | `Unit No. 5, 12 Smith St`, `Apartment Number 5, 12 Smith St` |
| CAR_WORD_JOINED | `Car Space` and `Car Park` (also with a hyphen) followed by an id are written as `Carspace` and `Carpark`, so they keep the G-NAF flat type (`CARS 12`, `CARP 3`) and never become a building named `CAR SPACE`. | `Car Space 12, 40 Smith St` |
| UNIT_NUMBER_JOINED | A unit number written with a dot between level and flat after a unit word (`Unit 3.02`, `Apt 1.05`), glued (`U3.02`) or before a slash (`3.02/12 Smith St`), and one written with a dash and a second part that starts with a zero (`Unit 12-05`), is one number with the parts joined (`302`, `105`, `1205`). G-NAF holds a flat as one integer (FLAT_NUMBER, up to five digits, see [data-sources.md](data-sources.md)), so a dot cannot be on the G-NAF side and the joined number is the key that can match it. A dash with no leading zero (`Unit 5-6`) is not joined, because it may be a range of units. | `Unit 3.02, 12 Smith St`, `Unit 12-05, 100 Smith St` |
| UNIT_AFTER_STREET | A unit word and its id straight after the street type (or after the suffix behind it) is the unit: `12 Smith St, Unit 5`, `12 Smith Street Apt 6`, `12 Smith St North #5`. The word must follow a street type that has a name before it, so a word inside a street name is never taken, and a unit already read in front is kept: the same unit twice is read once, two different units are not guessed between and the second stays where it was. | `12 Smith St, Unit 5, Fakeville NSW 2000` |
| BRACKET_NOTE_DROPPED | Text in brackets is a note and is dropped with its brackets; one never closed ends at the next comma or at the end of the line. | `12 Smith St (rear), Fakeville NSW 2000` |
| COUNTRY_DROPPED | `Australia`, `AU` or `AUS` as the last comma chunk, or as the last word straight after a state or a postcode, is dropped. A street or suburb that has the word in its name is not a country (`Australia St`, `Australia Fair`). | `12 Smith St, Fakeville NSW 2000, Australia` |
| FLAT_TYPE_KEPT | `Carspace`, `Carpark`, `Garage` or `Store` followed by an id: the unit key keeps the G-NAF flat type code first (`CARS 12`), because carspace 12 is not unit 12. | `Carspace 12, 40 Smith St` |
| UNIT_PREFIX_FORM | A letter prefix in front of the unit before the slash. | `G01/12 Smith St` is unit `G1` |
| LEVEL_PREFIX_FORM | `L` and a level before the slash is a level, not a unit, and so is a level word (`Level`, `Lvl`, `Floor`, `Flr`, `Ground Floor`, `3rd Floor`) and its level before the slash: the same address as the comma form `Level 2, 45 Pitt St`. An id with a letter before its digits after the word (`Level B2/12`) is not read as a level. | `L3/12 Smith St` is level 3, `Level 2/45 Pitt St` is level 2 of number 45 |
| LEADING_ZERO_DROPPED | A leading zero in a unit or level id, the way G-NAF stores the number. | `01/12 Smith St` is unit 1 |
| FLOOR_WORDS_READ | `Ground Floor` (also Level, Flr, Lvl) is level `G`, and `3rd Floor` is level 3. | `Ground Floor, 12 Smith St` |
| LEVEL_TYPE_KEPT | `Basement`, `Mezzanine` or `Podium` followed by an id: the level key keeps the G-NAF level type code first (`B 1`), because basement 1 is not level 1. | `Basement 1, 40 Smith St` |
| UNIT_MARKER_GLUED | The marker and the id written together. A glued marker takes digits with an optional letter after them (`U5`, `#5`, `U5A`); an id with a letter before its digits (`G1`) needs a space after the marker (`# G1`, `Unit G1`), so `#G1, 5 Hill St` is not read as a unit. | `U5/12`, `#5` |
| UNIT_SLASH_FORM | `unit/number`. | `5/12 Smith St`, `5A/12-14 Smith St` |
| UNIT_SLASH_SPACED | Spaces around the slash between a unit and a number are removed before anything is read, so `4 / 18` is unit 4 of number 18. A slash that is not between a unit and a number is left alone. | `4 / 18 St Ingowick Street`, `Unit 4 / 18 St Ingowick Street` |
| NUMBER_SUFFIX_SPACED | A single letter after the house number, with a space or a dash, is the number's suffix when a street name and a street type still follow it: `4 A St Ingowick Street` is number 4A and never number 4. A letter with only a street type after it is the street (`12 A Road`). A street whose name starts with a lone letter written with a space (`5 O Connell Street`) is read as number 5O. | `4 A St Ingowick Street`, `4-A St Ingowick Street` |
| LEVEL_MARKER | `Level`, `Lvl`, `L`, `Floor`, `Flr` followed by an id or `G` or `Ground`. | `Level 3 Suite 7, 12 Smith St` |
| LOT_MARKER | `Lot` followed by an id. | `Lot 7 Smith Rd` |
| LOT_PLAN_DROPPED | A plan reference after the lot id (`DP`, `SP`, `LP`, `RP`, `CP` or `PS` and its digits, with a space, a comma or a slash before it, or glued as `DP12345`) and the word `on` after it are not part of the street: they are dropped, so the lot is read as the lot and the street keeps its name. A plan word with no digits behind it (`Lot 5 Dp Smith Rd`) and a street that starts with `On` (`Lot 12 Onslow Rd`) are left alone. | `Lot 5 DP 12345, Smith Rd`, `Lot 12 on Smith Rd` |
| NUMBER_RANGE_READ | A street number range written with spaces, another dash (an en dash, an em dash, the minus sign), an ampersand or the word `to` is the range `12-14`. A pair of numbers straight after a unit, level or lot word (`Unit 3 & 4`) is not a house number range and is left as written. | `12 - 14 Smith St`, `12 & 14 Smith St`, `12 to 14 Smith St` |
| STATE_DOTS_REMOVED | A state written with dots between its letters (`N.S.W.`, `A.C.T.`, `Q.L.D.`, `W.A.`, with or without the last dot or with spaces) loses the dots before anything is read, so the state is read, `St` after it is not turned into SAINT and the suburb is not eaten. A state with only a trailing dot (`Qld.`) was never a problem. | `12 Smith St, Fakeville, N.S.W. 2000` |
| BUILDING_NAME_PREFIX | Words before the first unit, level or number, with no digit in them. Read with a comma after them or without one. | `Skyline Tower, Unit 5, 12 Smith St` |
| STREET_TYPE_EXPANDED | Every street type G-NAF lists (275 in STREET_TYPE_AUT, by its code or its short name: `Gdns` is GARDENS, `Hts` HEIGHTS, `Prom` PROMENADE) and the common spellings in `STREET_TYPE_SPELLINGS` (`St`, `Str`, `Rd`, `Ave`, `Dr`, `Ct`, `Pl`, `Cres`, `Ln`, `Tce`, `Pde`, `Cl`, `Blvd`, `Hwy`, `Cct`, `Esp`, `Gr`, `Sq`) become the full word. | `Smith St` |
| STREET_SUFFIX_KEPT | A STREET_SUFFIX_AUT name (NORTH, UPPER, NORTH EAST ...) after a street type that has a name before it, or a compass code (N, S, E, W, NE, NW, SE, SW). It stays with the type: `STREET NORTH`. | `12 Smith St North`, `12 Smith St N` |
| MOUNT_EXPANDED | `Mt` becomes `MOUNT` in a street or suburb name. | `Mt Pleasant Rd` |
| SUBURB_WORD_EXPANDED | `Nth`, `Sth` and `Pt` become `NORTH`, `SOUTH` and `PORT` in a suburb name only. | `Nth Sydney` |
| SAINT_EXPANDED | `St` becomes `SAINT` when it starts a street name, and everywhere in a suburb name. At the end of a street it is the type `STREET`. | `St Kilda Rd`, `St Albans` |
| STATE_NAME_TO_CODE | `New South Wales` becomes `NSW`, and the other eight (the state list is G-NAF's, with `OT`, Other Territories). | `Victoria` |
| SUBURB_FROM_LINE | The suburb, state and postcode were read from the end of the address line, for each of them that the feed's own columns leave blank. A comma between the suburb, the state and the postcode is a separator the same as a space (`Fakeville, NSW, 2000`), and so is a comma after the unit with none before the suburb. A feed whose suburb, state and postcode columns are all blank is a feed with no such columns. | `5/12 Smith St, Fakeville NSW 2000`, `77 Ingenfield Road, Corrmorville, QLD 4760` |
| LINE_TAIL_REPEATED | The end of the line repeats what the columns already say (the same suburb, state or postcode), so it is dropped from the street and read once. A tail that contradicts a column is left where it was and the column wins; nothing is guessed away. | `12 Smith St, Fakeville NSW 2000` with the columns Fakeville, NSW, 2000 |
| SUBURB_SPLIT_HEURISTIC | No comma told where the street ends, so the first common street type word with a name before it and something after it ends the street. Only when no common type splits the words is a type that only G-NAF lists tried (`5 Park Gdns Fakeville NSW 2000`). A suffix written after that point is read as part of the suburb. It also runs when the line ends with a suburb and no state or postcode and no column gives the suburb (`12 Smith St Fakeville`, `7 Station St Mt Druitt`), when the words after the street type look like a suburb: no digit, no unit, level or lot word first, no street type last, and no street suffix (`12 Smith St North` keeps its suffix). A suburb that ends in a street type word (`Elizabeth Grove`) is not split without a state or postcode, because the last word may be a second street. | `12 Smith St Fakeville NSW 2000`, `12 Smith St Fakeville` |
| POSTAL_ADDRESS | A `PO Box`, `P.O. Box`, `GPO Box`, `Locked Bag` or `Private Bag` anywhere in the address. Nothing else is read from it: the address has no street, and the match stage sets the record aside with this reason. | `PO Box 5 Fakeville NSW 2000` |
| POSTCODE_ZERO_RESTORED | A three digit postcode with state NT gets its leading zero back (a spreadsheet drops it). | `800` is `0800` |
| POSTCODE_MISSING, POSTCODE_BAD_SHAPE | The postcode is empty, or is not four digits (and is not an NT postcode that lost its zero). It is left empty, never guessed. | `2000x`, `200` |
| STATE_MISSING, SUBURB_MISSING | Nothing to read it from. Left empty. | |
| COORDS_OUT_OF_RANGE | A listing latitude or longitude is not a number or is outside Australia. The coordinates are dropped. | `33.8` (a missing minus sign) |

Never done: the letter O is not read as the digit 0, a postcode is not inferred from a suburb, a state is never filled into a record from its postcode (the canonical key below does use the postcode's range, and only there), a street name is not spell corrected here (that is the match stage's job, with a threshold and a tie rule). A flat type that is not one of the carspace, carpark, garage and store words is read as an ordinary unit: `Shop 3` and `Unit 3` in one building are one unit key. The G-NAF flat types kept apart are in `DISTINCT_FLAT_TYPES` (ANT, ATM, BBQ, BTSD, CAGE, CARP, CARS, COOL, GRGE, MBTH, SHED, SIGN, STOR, SUBS, VLT); the other 38 count as a unit. A tower letter or a building name written before a unit and then a number (`Tower A, Unit 5, 12 Smith St`, `Unit 5, Harbour View Apartments, 12 Smith St`) is not read: the record is UNPARSEABLE (`Tower 3, Unit 5, ...` with a number works). A suburb whose last word is a street type (`Elizabeth Grove`) is split from the street only when a state or postcode follows it.

## What a canonical key is

`Addr.canon_key` is `level|unit|lot|number|street name, type and suffix|locality|state`. A unit or level key that keeps a type reads `CARS 12` or `B 1`. The postcode is left out on purpose: a feed that drops or mistypes it must not make a second derived property for one address. The building name is left out too, because it is written differently everywhere.

**A blank state.** When the state column is blank the key takes the state from the postcode's range (`state_for_postcode`: 2000 to 2599 NSW, 2600 to 2618 ACT, 3000 to 3999 VIC and so on, Australia Post's ranges), so one address from a feed that writes the state and a feed that leaves it empty is one derived id. A written state is never replaced. The stored state of the record stays blank and matching still treats it as unknown; only the key is completed. A postcode in no range gives no state, and an address with neither state nor postcode keeps a blank state in its key, so it is a different id from the same address with a state: the data does not say which state it is in.

## Phones

`normalise_phone` returns E.164 (`+61412345678`) or an empty string.

| Rule id | Fires when |
|---|---|
| PHONE_COUNTRY_CODE_STRIPPED | `+61`, `0061` or a leading `61` on a number of 11 or more digits was removed. |
| PHONE_TRUNK_ZERO_STRIPPED | The leading `0` was removed (also the `(0)` in `+61 (0)2 5550 1234`). |
| PHONE_E164 | The rest is a mobile (`4` and eight digits) or a landline (`2`, `3`, `7` or `8` and eight digits). |
| PHONE_PLACEHOLDER | A mobile or landline whose last eight digits are one digit (`0400 000 000`, `0411 111 111`, `02 2222 2222`): a form filled with a placeholder, never one person's number. Also fires PHONE_INVALID and gives no number. |
| PHONE_INVALID | Anything else: no area code, a 13 or 1300 or 1800 number, a foreign number, a placeholder, text such as `tbc`. Not guessed. |

## Emails

`normalise_email` trims, removes `mailto:` and angle brackets, drops a display name written in front of the brackets (`Kate Smith <kate@example.com>` is `kate@example.com`), drops a trailing `;`, `,` or `.` and a trailing note in brackets (`kate@example.com;`, `kate@example.com (Kate)`; rule EMAIL_TAIL_DROPPED) and lower-cases. Two addresses in one cell (`a@x.com; b@y.com`) are not one address: they are refused with EMAIL_INVALID, never read as the first. The local part is never edited beyond case: dots are not removed from a Gmail style address and plus tags are not cut, because that would be guessing. Every character the standard allows in an unquoted local part is kept, the apostrophe of `sean.o'brien@example.com` among them; a space, a comma, a bracket, a quote or a second at sign is still invalid. A short list of placeholders a form is filled with when the person gave none (`noemail@noemail.com`, `noemail@email.com`, `noemail@gmail.com`, `nomail@nomail.com`, `no@email.com`, `none@none.com`, `no@no.com`, `na@na.com`, `n@n.com`, `a@a.com`, `test@test.com`, `email@email.com`, `unknown@unknown.com`) is refused with EMAIL_PLACEHOLDER and EMAIL_INVALID, so it never merges two contacts; the same local part on another domain is kept. Rules: EMAIL_TRIMMED, EMAIL_MAILTO_STRIPPED, EMAIL_TAIL_DROPPED, EMAIL_NAME_DROPPED, EMAIL_LOWERCASED, EMAIL_PLACEHOLDER, EMAIL_INVALID.

## Names

`normalise_name` only collapses spaces. A name is shown and never matched on.

## How it is tested

`tests/test_normalise.py` holds one generated table per class of fix (flat and level types, street suffixes, mailboxes, unit prefixes and leading zeros and floor words, street types, NT postcodes and Other Territories), each with the harmful input and the ordinary input it must not break; `tests/test_ordinary_addresses.py` pins 40 everyday addresses to the parts and rule ids the first build gave them; `tests/test_corpus.py` replays the review corpora (the second one through the real pipeline against the generated world); `tests/test_address_forms.py` and `tests/test_email_forms.py` hold the generated tables of the third review (unit and number separators, a letter after the number, how an address is split across columns, commas, a blank state, email characters and display forms) and, for the fourth review, a unit written as a letter, behind a word with a number, after the street or with a dot, a trailing country or bracket note, and trailing punctuation on an email; and, for the fifth review, a level word before a slash, a house number range with spaces or another dash, a dotted state, a suburb with no state behind it, a lot with a plan reference, a placeholder phone and email. Also: a table of every unit form from the brief, one test per street type spelling, every state name and code, Mount and Saint in street and suburb, lots, building names, the tail of a one line address, a table of phone forms with the rules that must fire and a table of numbers that must not be guessed. Hypothesis properties: normalising the canonical line gives the same address, unit and number are read back from any spelling, normalising any text never raises, phone and email normalisation are idempotent. The mutation check requires a failing test for each change to the module.
